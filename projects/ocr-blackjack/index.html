The problem

The OCR service provides recognized cards for each hand, without blackjack game logic. My Go backend turns that data into game state and historical records; a colleague trained the recognition model.

The monitor

I developed three applications around the OCR output: a Go backend, a React web interface and a Godot camera-settings app. A colleague trained the blackjack OCR model. Using an AI-assisted development workflow, I defined the requirements, data structures and APIs, guided implementation, integrated the applications, and handled debugging, testing and deployment.

The Go backend derives player counts, hand totals and game results from the OCR data. It treats an empty card state as the start of a new round.

The React interface provides current-game monitoring, searchable and filterable history, CSV export and replay of recorded card updates. Each game’s data is saved as JSON in a database and remains available after backend restarts.

The backend automatically reconnects to the OCR service and continues the current round. I verified this in internal testing and ran automated tests for round segmentation and removal alongside manual testing.

The calibration tool

The Godot app lets users adjust the camera’s detection regions, then asks the backend to restart the OCR service with the updated camera settings.

Outcome

I completed the Go backend, React web interface and Godot camera-settings app in a little over a month, using an AI-assisted workflow. The tools were tested internally; development is currently on hold.
