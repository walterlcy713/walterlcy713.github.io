The attraction

Visitors fold an origami animal or complete a colouring sheet, then see their creation appear in an interactive city. I built the two Unity visitor apps and the Go backend connecting registration to the Unreal show.

  1. The tutorial station teaches the origami step by step, and tells visitors about the real animal they are folding.
  2. The kiosk sends an image of the visitor’s creation to a colleague’s recognition service, which returns the creation ID and a cropped image. The kiosk keeps those results while the visitor completes registration, including a portrait photo. After registration, the system randomly selects a gacha shell.
  3. The show backend queues the completed registration. The Unreal show consumes the registration data over WebSocket and displays the corresponding gacha shell, creation image and visitor portrait in the projected city.

Both visitor apps support English, Traditional Chinese and Simplified Chinese, including the tutorial’s animal descriptions.

The tutorial station

I designed the tutorial around Unity ScriptableObjects so I could add new animals by supplying their assets and content data, without changing the application code.

I implemented chapter navigation, video seeking and playback-speed controls, plus an idle timeout that returns the app to attract mode.

The kiosk — reliability and remote support

I built the kiosk in Unity with UI Toolkit, handling image and portrait capture, integration with a colleague’s recognition service, and registration with the show backend. After registration, the system randomly selects a gacha shell.

I built the Unity kiosk and tutorial apps and the Go backend. Development began in late 2024, with roughly three to four months of development and testing. A colleague handled on-site setup and testing; my support was remote.

I fixed memory leaks in texture buffers and added camera recovery, frame-timeout checks, guards against repeated button presses and file logging for remote troubleshooting.

Persistent camera-related crashes prompted me to try replacing Unity’s built-in webcam layer. Using an AI-assisted workflow, I developed a native C++ camera plugin and C# integration and deployed it to the live kiosk. The situation improved, but crashes persisted.

Two kiosks had the same setup: one ran without this problem, while the other kept experiencing it. The persistent fault was ultimately traced to a cable on the affected on-site machine. The plugin was a production integration and a troubleshooting step; it did not resolve the underlying cable fault.

The show controller

I designed the data formats and API, and implemented the WebSocket integration between the Go backend and the Unity kiosk.

Once kiosk registration is complete, it submits the collected information to the Go backend. The backend stores it in a queue for the Unreal show to consume over WebSocket, including the recognised creation ID, cropped creation image and visitor portrait.

I designed and implemented the backend’s display allocation, content-type and duration rules, and special-event handling. The web dashboard was developed by others.

Outcome

As the systems stabilized, bug-fix and maintenance work became less frequent. I continue to provide occasional updates and remote technical support.
